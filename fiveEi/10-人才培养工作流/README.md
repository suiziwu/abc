# 人才培养方案智能数据工作流

把「材料」变成「人才培养页面可直接渲染的数据表」的 Python 工作流。

- **不写死内容**：岗位、技能、缺口、趋势、预警、建议全部来自你传入的材料 + DeepSeek 实时生成。
- **不落文件**：核心函数 `generate(payload)` 直接返回 `dict`（表结构 + KPI + 图表数据），命令行只打印到标准输出。
- **提示词可改**：模型、接口地址、提示词、并发、校验阈值都在 `config.json`，改提示词不用动代码。
- **可核验**：每条预警/建议都必须带来源编号和原文证据，流水线会自动校验并在不合格时让模型自己修一轮。

## 一、目录


## 三、工作流做了什么

```
材料分片（按来源，1000 字/片，带重叠）
   ↓ 并发调用 DeepSeek，每片抽 岗位 / 技能 / 指标 / 趋势（带原文证据）
合并去重（岗位、技能按归一化键合并；指标按 指标+数值+单位+来源 去重）
   ↓ 统计技能提及次数、热度指数
技能能力域归类（模型，失败则标“未分类”，不影响主流程）
   ↓
生成预警与培养建议（模型，强制引用来源编号）
   ↓
引用校验：来源编号是否存在 / 证据是否出自原文 / 预警数字是否能在原文找到
   ↓ 不通过 → 把问题回传给模型修一轮 → 再校验
组装：KPI + 5 张表 + 3 组图表数据 + 来源清单 + 校验结果 + 告警
```

## 四、输入格式

```jsonc
{
  "专业群": "智能制造专业群",
  "区域": "广东东莞",
  "面向岗位": ["工业视觉系统运维员", "工业机器人系统运维员"],
  "数据源": [
    {
      "id": "S1",                     // 可选，缺省自动编号 S1、S2…
      "标题": "锻造高素质技能人才队伍",
      "来源": "人力资源和社会保障部",
      "类型": "官方",                 // 官方 / 国家职业标准 / 媒体 / 行业 / 招聘平台 / 企业
      "发布时间": "2026-10-08",
      "正文": "据测算，2025年全国数字经济、智能制造相关领域的高技能人才缺口已突破千万。……"
    }
  ],
  "岗位样本": [                        // 可选：招聘平台岗位样本，用于算技能热度
    { "职位名称": "工业视觉系统运维员", "技能": "机器视觉, 视觉检测, PLC", "城市": "东莞" }
  ]
}
```

- `数据源` 与 `岗位样本` 至少给一个。
- 材料越长越要拆成多条（一条一个来源），便于分片并发和引用定位。
- `面向岗位` 会强制出现在岗位需求表里；材料没提到时标“待补录”，页面不会空。

## 七、配置说明（`config.json`）

| 字段 | 作用 |
|---|---|
| `api.base_url` | 接口地址。DeepSeek 默认 `https://api.deepseek.com`；换成任意 OpenAI 兼容服务也可以 |
| `api.model` | 模型名，默认 `deepseek-chat` |
| `api.api_key_env` | 读 Key 的环境变量名，默认 `DEEPSEEK_API_KEY` |
| `api.max_retries` | 429 / 5xx / 网络异常的重试次数 |
| `api.json_mode` | 是否启用 `response_format=json_object`（模型不支持就设 `false`） |
| `workflow.max_workers` | 分片并发数，材料多时调大（注意限流） |
| `workflow.chunk_chars` | 每片字符数，默认 1000 |
| `workflow.max_chunks` | 最多处理多少片，超出会告警并截断 |
| `workflow.max_repair_rounds` | 校验不通过时自动修复几轮，默认 1 |
| `workflow.evidence_min_similarity` | 证据与原文的最低相似度，低于此值判为“不匹配” |
| `prompts.*` | 全部提示词。占位符写成 `${专业群}`、`${片段}` 这种形式 |

**换模型**：只改 `api.base_url` 和 `api.model`，例如本地 Ollama：

```json
"base_url": "http://127.0.0.1:11434/v1",
"model": "qwen2.5:14b",
"api_key": "ollama",
"json_mode": false
```

## 八、稳定性设计

1. **JSON 兜底**：模型偶尔会把 `{"type": "json_object"}` 原样吐回来，客户端识别到这种占位输出会自动关掉 JSON 模式再要一次。
2. **单点失败隔离**：某个片段抽取失败只记告警，不影响其他片段；全部失败才报错。
3. **引用校验**：来源编号必须存在、证据必须能在原文里找到（相似度 ≥ 阈值）、预警里的数字必须出现在引用来源中。
4. **自动修复**：校验不通过时把问题清单回传模型修一轮，再校验。
5. **降级**：建议生成失败时，页面仍然能拿到 KPI 和统计表，只在 `warnings` 里说明。
6. **不编造**：提示词明确“材料没有的类别输出空数组”，`数据缺口表` 用来诚实标注拿不到的数据。

## 十、注意

- **不要提交 API Key**。`config.json` 里的 `api_key` 留空、用环境变量最稳妥；仓库里旧脚本中的明文 Key 建议去 DeepSeek 控制台重置。
- 输出里的“证据原文”是模型摘录的，**答辩前建议人工抽查一遍**，尤其是数字和口径。
- 材料里没有量化数据时，`最大人才缺口` 会显示 `—`，这是刻意设计：宁可不给，也不推算。

## 十一、预生成模式：直接生成看板页面

适合答辩 / 离线演示：先把数据生成好，页面打开只读本地 `数据.js`，**不调接口、秒开、零成本**。

```
10-人才培养工作流/
├─ 生成页面数据.py        # 调一次工作流，写 数据.js（并给 index.html 打版本号）
└─ 网页看板/
   ├─ index.html          # 看板页面（静态）
   ├─ 数据.js             # window.TALENT_DATA = {...}，页面同步加载
   ├─ 数据.json           # 同样的数据，留作排查/二次使用
   ├─ 预览.png            # 渲染效果截图
   └─ assets/
      ├─ render.js        # 把数据刷进 KPI / 表格 / 预警 / 建议 / 缺口 / 来源
      └─ charts.js        # 三张图从 window.TALENT_DATA.charts 取数
```

### 生成 / 更新

```powershell
python 生成页面数据.py                 # 用 示例输入.json，重新调接口生成
python 生成页面数据.py 我的材料.json     # 换一份输入
python 生成页面数据.py --复用           # 不调接口，用现有 数据.json 重写页面数据
```

然后双击 `网页看板/index.html` 即可。

- 每次生成都会把 `index.html` 里 `数据.js?v=...` 的版本号换掉，避免浏览器缓存旧数据。
- 想换材料：改 `示例输入.json`（或另写一份），重跑脚本，页面代码一行都不用动。
- 页面里 **没有任何 fetch / 后端**：`数据.js` 用 `<script>` 同步加载，`file://` 直接打开也不受跨域限制。
